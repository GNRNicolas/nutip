# Nutip

A folder of things the user kept deliberately, one Markdown file each, with a
`why` line: their reason, which nothing else in the folder carries. `nutip path`
prints the folder, `nutip doctor` the whole setup.

## Answering from what they saved

Search first, open two or three files, and quote the `why`. Never read the
whole folder: the index lines already carry the date, title, source, tags and
reason, which is usually enough to pick what is worth opening.

```sh
nutip search "pricing #competitors" --json   # newest first; each row has an absolute `file`
nutip search claude                          # same, plain text
nutip recent 20                              # what they kept lately
nutip tags                                   # the tags they use
```

`#tag` inside the query restricts to a tag. Tags keep their capitals and
accents but match without them: `#Veille`, `#veille` and `#veillé` are one tag.

Pass the user's question as it is: words are OR'd and the best match comes
first, so extra words cost nothing and a tag is the only thing that is
required.

**When search comes back empty, do not stop there** — it matches words, and
the question rarely uses the words the page used. Escalate, cheapest first:

1. **Ask again in the other language.** This is the single biggest win and it
   costs one command: the folder holds English pages and the questions come in
   French, or the reverse. Measured on a 19-clip corpus: 5 French questions out
   of 10 found their clip; the same 5 failures, re-asked in English, found it
   every time — 10/10. Translate the subject words, not the sentence
   (*"effets de bord react"* → `useEffect side effects react`).
2. `nutip tags`, then the page of the likeliest tag (`tags/<tag>.md`) — a few
   hundred tokens, already narrowed.
3. `nutip recent 200`, or `INDEX.md` at the root: one line per clip, with its
   reason. Read it and make the connection yourself — that is the step no
   full-text index can do, and it is why the folder is written this way.

Two searches with different words are cheaper than one wrong "I found
nothing". Never answer that a clip does not exist without having read an
index page.

**Without the CLI** (another machine, app not installed), the folder alone is
enough: read `AGENTS.md` at its root, then `INDEX.md`, then `tags/<tag>.md` or
`YYYY-MM/INDEX.md`. `grep -rl "^tags:.*veille" .` works too.

## Saving

```sh
nutip add "https://example.com/post" -t reading -w "the pricing table"
nutip add "https://example.com/post" -t reading -x     # -x also fetches the page text (blocks a few seconds)
nutip add "some text" -t ideas -w "why it matters"     # or pipe text on stdin
```

Always pass `-w`: a clip without a reason is the one they cannot use later.
Use a tag from `nutip tags`; if a new one is genuinely needed, create it with
`nutip tags add <tag>` rather than inventing it in a file, or the palette will
never offer it. Never save credentials, tokens or private keys: this folder is
often in a Git repo.

## Tidying

The files are the truth; the index pages are generated and rewritten.

```sh
nutip rm 2026-09/2026-09-13-some-title.md    # trashes one clip, indexes updated, no confirmation
nutip reindex                                # after editing any file by hand
```

```sh
nutip enrich            # gives keywords to the clips that have none
nutip enrich --dry-run  # shows what it would write, changes nothing
```

`keywords:` in the frontmatter is what the clip is about, counted from its own
text — no model, nothing sent anywhere. It is indexed, so it widens what a
search matches. Worth running after a batch import; a `keywords:` line that
already exists is never touched, so correcting one by hand sticks.

To retag or fix a clip, edit `tags:`, `why:` or `keywords:` in its
frontmatter, then `nutip reindex`. Never edit `INDEX.md`, `AGENTS.md`, `README.md`, `tags/*.md`
or `YYYY-MM/INDEX.md`: they start with a "generated by Nutip" comment and are
overwritten on the next clip.

## Settings

```sh
nutip folder                      # where the clips are
nutip folder ~/notes/clips        # move to another folder (creates it)
nutip tags add veille pricing     # what the palette offers; nutip tags rm to drop one
```

A running Nutip picks these up immediately.

## Rules

- Do not bulk-delete or bulk-retag without asking: these are the user's own
  notes, and the app's undo only covers the last clip saved from the palette.
- Do not change the folder or remove tags unless asked; both change what the
  user sees when they press the hotkey.
- When you report a clip back, quote its `why`: it is why they kept it.
